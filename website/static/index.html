Stop restarting SAP Commerce to test a code change

Reclazz loads your changed Java classes into the server that is already running. Change a method, build, refresh the page. No restart, and you stay logged in.

Install the IntelliJ pluginHow to set it up

Free and open source. Java {{CLAIM:agent_java_min}} or newer.

What happens in the video

Setup takes a few minutes

The plugin opens a setup window the first time you open your project. For SAP Commerce it adds two lines to local.properties, runs ant server for you, and tells you when to restart once. For a Spring Boot or plain Java project you only switch Reclazz on.

  1. 1. Add the agent to local.properties

    The plugin shows the two lines before it writes them. You can remove them again with one click.

  2. 2. Run ant server

    The wizard runs it and shows the output. If your server is still running, it tells you to stop it first.

  3. 3. Connect an AI assistant (optional)

    Lets Claude Code, Cursor or Codex see whether a change was reloaded. Skip it if you don't use one.

Open the setup guide

A restart for every change adds up

Every SAP Commerce restart means waiting for the server to start, logging in again and clicking back to the page you were testing. Ten changes a day is a lot of waiting.

Without Reclazz

Build. Restart the server and wait. Log in again. Find your page. Check the change.

With Reclazz

Build. Refresh the page. Check the change.

What you can change without a restart

Method bodies, new methods, Spring beans, configuration, JSP and ImpEx, and more. Some changes, like changing a class's superclass, still need a restart. Reclazz tells you when that happens and which file caused it.

How it works

What still needs a restart

A Java agent watches compiled output in your application. A method-body edit keeps existing object fields. A refreshed Spring bean can lose its mutable state. Changing a superclass requires a restart.
