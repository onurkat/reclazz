Documentation/Reload support matrix
Reload support matrix

Will your change reload?

Find the outcome, exact conditions and next action for the edit you want to make.

Start with the change, then read its conditions. A reloaded class does not automatically mean refreshed framework metadata or a changed database schema.

Scope travels with the claim

These outcomes come from the canonical support reference. Consult the evidence baseline for measured runtime lanes. They are not a promise for every release, framework version or object shape. Read the evidence model.

JavaEdit an existing method bodyReloads

Compile a supported edit into a watched output. Existing object fields remain on the JVM method-body-only path. Framework follow-up can separately recreate beans.

Next: Compile, check the same JVM and inspect the changed result.

JavaAdd or remove a methodConditional

Stock-JDK companion mode supports hot-compiled calls; new methods do not become native members of the original Class. Previously held removed members can retain their last implementation.

Next: Compile affected watched callers; use a supported framework adapter for reflection.

Read conditions & scope →
JavaAdd an instance fieldConditional

Stock mode stores added fields separately. Isolated initializers run on first read for existing objects; constructor-dependent or entangled initializers retain type defaults with a reason.

Next: Read the initializer diagnostic and verify an existing object.

Read conditions & scope →
JavaRead/write an added field from another classConditional

Both owner and caller must be watched/reloaded in the measured direct-access shape. Field-type changes and every inherited/loader variant are not certified.

Next: Compile both sides and check the shared value on an existing object.

Read conditions & scope →
JavaAdd a static field with an initializerConditional

Compile-time constants and separable initializers, including bounded forward conditionals/switches, are supported. Existing static blocks and values are not reset.

Next: Check the new value and any extraction refusal reason.

Read conditions & scope →
JavaChange an already initialized static field initializerRestart

Later saves preserve the current added static value, including null or application writes. Reload does not replay arbitrary static initialization.

Next: Restart to run startup initialization again; account for external side effects.

Read conditions & scope →
JavaChange an inlined compile-time constantConditional

Callers can retain their old literal until recompiled. AutoCompile can rebuild detected watched sources; unwatched consumers remain outside that repair.

Next: Recompile affected callers or use supported AutoCompile.

Read conditions & scope →
JavaAppend an enum constant / remove its final constantConditional

Documented on JDK 17–25 with ordinal-preserving edits. Existing application arrays sized from the old enum length do not grow.

Next: Check enum consumers and any fixed-size application arrays.

Read conditions & scope →
JavaInsert/reorder enum values or remove a non-tail valueRestart

The edit renumbers ordinals; Reclazz refuses it. Restart alone does not migrate persisted ordinal data.

Next: Review persisted ordinals and restart for the type change.

Read conditions & scope →
JavaAdd or remove an implemented interfaceConditional

Requires a compatible enhanced-redefinition JVM such as JBR/DCEVM. Stock JVMs refuse the type change.

Next: Use a supported enhanced runtime or restart.

Read conditions & scope →
JavaChange a superclassRestart

The loaded superclass stays unchanged. Eligible bodies may apply; dependent methods stay pinned and unsafe signatures/constructors can refuse the whole save.

Next: Read partial/refused reporting and restart for the hierarchy.

Read conditions & scope →
JavaDiscover added members through arbitrary reflectionRestart

On stock JVMs the original Class lacks companion members. Explicit framework adapters have separate scope; arbitrary reflective consumers do not.

Next: Restart, or use a compatible enhanced JVM/explicitly supported adapter.

Read conditions & scope →
JavaAssume every Java 17+ vendor/version is certifiedUnverified

Java 17+ is the target. The main recorded portable lanes are stock SapMachine 17/21 on macOS arm64, not every vendor, OS or future JDK.

Next: Validate the exact runtime and change shape.

Read conditions & scope →
SpringRefresh an affected singleton beanConditional

Supported bean paths destroy/recreate the singleton and repair bounded references. Mutable bean state can reset; arbitrary external holders are not repaired.

Next: Check lifecycle effects, current references and the served result.

Read conditions & scope →
SpringAdd a new component classConditional

Direct/composed stereotypes, native name/condition selection and singleton/prototype/lazy creation are supported. Not a repeat of full startup scanning.

Next: Compile the new class and check registration/condition outcome.

Read conditions & scope →
SpringAdd a component with a web/custom scope or scoped proxyRestart

The new-component path refuses these scope shapes. Normal singleton/prototype support does not imply custom scope enrollment.

Next: Restart under the application’s normal configuration.

Read conditions & scope →
SpringReevaluate every filtered component after a profile/property editUnverified

New-component conditions are registration-time decisions. General later rediscovery and startup import/auto-configuration replay are outside this path.

Next: Use a restart for a changed startup topology; validate any narrower path.

Read conditions & scope →
SpringAdd an @Bean factory methodConditional

Bounded lite/full/static configuration paths support documented arguments, aliases, selection and direct conditions. Existing names/custom scopes/unknown composed conditions are restricted.

Next: Use the exact factory allowlist and check product identity/lifecycle.

Read conditions & scope →
SpringChange existing injection or lifecycle metadataConditional

Spring metadata caches are refreshed on supported bean paths. Recreation has state and reference limits; it is not an arbitrary graph rewrite.

Next: Check the recreated bean’s injection and lifecycle behavior.

Read conditions & scope →
SpringAdd @PostConstruct / @PreDestroy methodsConditional

Supported plain singletons use the javax Spring 5 / Jakarta Spring 6 lanes. Each instance keeps its added destroy callback through later edits/removal.

Next: Verify creation/injection/destruction for the affected instance.

Read conditions & scope →
SpringAdd @Transactional or cache-advised service methodsConditional

Supported public singleton operations use native interceptors; bounded composed metadata is supported. Compile the caller and respect the proxy/advice allowlist.

Next: Verify commit/rollback or cache behavior, not only the method result.

Read conditions & scope →
SpringAdd pre/post authorization to a new service operationConditional

Named classic/modern Spring Security graphs support direct and bounded composed policies. Unknown security infrastructure/advice shapes are refused.

Next: Check both allowed and denied calls with the installed security graph.

Read conditions & scope →
SpringEdit an @Aspect pointcutConditional

Updates supported existing mutable singleton JDK/CGLIB proxy chains. Previously unproxied targets and unsupported proxy shapes are outside this path.

Next: Check an already-injected reference and inspect unsupported targets.

Read conditions & scope →
SpringAdd/edit/remove @Scheduled methodsConditional

Direct no-argument void callbacks on supported singletons, with documented proxy/transaction/cache/async combinations. Removal cancels the registration.

Next: Check one current schedule and retirement of its predecessor.

Read conditions & scope →
SpringAdd/edit/remove @EventListener methodsConditional

Direct callbacks with one reference event input and void/single-event return on supported singletons. Filtering/order/conditions and advice have bounded scope.

Next: Publish a test event; check current delivery and no stale registration.

Read conditions & scope →
SpringAdd @TransactionalEventListener methodsConditional

Direct void methods on supported unproxied singletons; Spring handles phase/fallback/conditions/order. Reload retires queued callbacks from the old added registration.

Next: Check the intended transaction phase and a later edit/removal.

Read conditions & scope →
SpringAdd @Async service methodsConditional

Direct public methods support void, Future and CompletableFuture with native executor/error handling and supported transaction/cache advice.

Next: Check execution, returned completion and exception handling.

Read conditions & scope →
SpringReload a helper captured by a constructor-injected leafConditional

Exact supported factories, plain two-node shapes and one measured direct-child context form. Aliases, broader graphs, proxies/factory products and lifecycle-owned shapes are excluded.

Next: Read the ownership contract and verify the retained caller’s value.

Read conditions & scope →
Web & JSONAdd/change a controller endpointConditional

Supported controller mapping rescans include added methods on stock JVMs. Receiver, metadata and classloader shapes still matter.

Next: Compile and send a request to the intended route.

Read conditions & scope →
Web & JSONAdd @ExceptionHandler methodsConditional

Plain controllers/advice and standard resolver on Framework 5.3.39/6.1.14; bounded synchronous metadata. Proxy/inheritance/generic/composed/custom resolver shapes are excluded.

Next: Check status/body and handler precedence; fix ambiguous mappings.

Read conditions & scope →
Web & JSONAdd @InitBinder / @ModelAttribute methodsConditional

Supported plain controller/advice adapters preserve named binding, model rules and native advice order/selectors. Read the exact callback allowlist.

Next: Check a real binding/model request through the current controller.

Read conditions & scope →
Web & JSONAdd Jackson getters, setters or DTO fieldsConditional

Supported Spring-managed mapper adapter; mutable DTOs and saved annotations. Final added fields are not writable; creator/record/builder additions are excluded.

Next: Check JSON input and output against the installed Jackson version.

Read conditions & scope →
Web & JSONAssume every serializer discovers companion membersUnverified

Jackson’s explicit adapter does not establish arbitrary Gson/custom mapper or record-creator support. Stock original-class reflection remains limited.

Next: Validate the serializer or restart for native reflective visibility.

Read conditions & scope →
Web & JSONChange validation constraints on an existing fieldConditional

Supported Hibernate Validator metadata caches are cleared in both javax/Jakarta factory discovery paths. Do not infer arbitrary validator/provider compatibility.

Next: Submit both invalid and valid input; inspect the native validation result.

Read conditions & scope →
Web & JSONEdit an existing Spring Security HTTP ruleConditional

Supported SecurityFilterChain beans rebuild into the live FilterChainProxy. Inline ignoring chains remain; a failed rebuild can keep the previous rules serving.

Next: Verify allowed and denied requests; inspect whether the new rules became live.

Read conditions & scope →
MessagingAdd/edit/remove a Kafka listenerConditional

Plain singleton, direct callback, explicit literal ID, documented topic/group/options and standard record-mode factory. Native consumers retire before replacement.

Next: Verify message delivery, new route and old-consumer retirement.

Read conditions & scope →
MessagingAdd/edit/remove a JMS listenerConditional

Plain singleton with standard processor/registry/default container factory. Literal or placeholder destinations/selectors; bounded result and callback shapes.

Next: Verify delivery/selector behavior and complete consumer destruction.

Read conditions & scope →
MessagingAdd synchronous JMS repliesConditional

Documented return types and direct @SendTo. JMSReplyTo takes priority; null sends nothing. No arbitrary DTO/Future/reactive return claim.

Next: Check conversion, correlation and destination on a test request.

Read conditions & scope →
MessagingAdd/edit/remove a Rabbit listenerConditional

Plain receiver, standard simple container, AUTO acknowledgment/default executor and bounded queue/options. Startup worker hook must track complete retirement.

Next: Wait for worker retirement and verify real message delivery.

Read conditions & scope →

Documented native SpEL values are reevaluated when the listener is saved. Evaluation occurs after old consumers retire and can fail without restoring them.

Next: Save the listener again and check the exact route/group.

Read conditions & scope →
MessagingReroute consumers by changing only a routing property/beanConditional

The documented added Kafka/Rabbit expression path does not automatically reroute on a property/bean-only edit; a listener re-save is the supported live action.

Next: Re-save/compile the listener, or restart for native startup resolution.

Read conditions & scope →

Separately measured narrow root-context leaf-owner transactions; exact factories, constructor and callback shapes. Not arbitrary consumer graphs.

MessagingRecreate Rabbit consumers through property/dependency cascadesConditional

Measured on Framework 5.3.39/AMQP 2.4.17 and Framework 6.1.14/AMQP 3.1.7, stock JDK 17/21 on macOS arm64: one root context, plain local helper/leaf owner, one void literal-ID callback, native simple containers, AUTO acknowledgment and nontransacted channels.

When a change spans more than one row

Apply the most restrictive relevant condition. Adding a model field can combine a supported bytecode change, a reflection restriction and a required schema update. Check each layer, then verify the runtime behavior. A partial or refused framework step should stay visible in the pending ledger.

“No reload” means this path applies no Reclazz change, including a valid no-op save or an unhandled file kind. “Unverified” is a missing acceptance result. It does not mean a feature always fails, and it should not be presented as guaranteed support. Use the pinned technical reference for version-specific test provenance.
