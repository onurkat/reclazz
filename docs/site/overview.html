Know exactly what “reload” means

A successful class replacement, a recreated bean and an updated database mapping are different outcomes. The guides keep those distinctions visible so you can choose the right edit and recovery path.

Reloads Supported within its stated scope Conditional Requires a particular mode or shape Restart This edit needs a restart Unverified Acceptance evidence is missing No reload No Reclazz change is applied
State is specific to the path

Method-body redefinition keeps existing object fields. A Spring singleton refresh destroys and recreates that bean and can reset its mutable state. Saving the previous code does not restore destroyed resources.
