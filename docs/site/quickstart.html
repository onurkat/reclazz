Install from JetBrains Marketplace (recommended)

For an application you run directly from IntelliJ, start here. No separate agent download is needed.

  1. Open IntelliJ IDEA and go to Settings → Plugins → Marketplace.
  2. Search for Reclazz, choose Install, and restart IntelliJ if prompted.
  3. Open your project. In Settings → Tools → Reclazz, tick Enable Reclazz in this project and choose Apply.
  4. Start your application with an IntelliJ-managed Java run configuration. Wait for Reclazz to connect.
  5. Change the text returned by an existing method, use Build Project, and call it again.

It worked when the same running application returns your new text; the Reclazz tool window also names the reloaded class.

IntelliJ: use an IDE-managed Java run

  1. Install Reclazz in Settings → Plugins → Marketplace, or install the release ZIP from disk.
  2. Enable Settings → Tools → Reclazz → Enable Reclazz in this project. Start an IDE-managed Java run configuration. The plugin supplies its bundled agent.
  3. Wait for the watcher to start. Startup attachment waits 30 seconds by default; record the current response before editing.
  4. Change the text returned by an existing method. Compile with the build that writes the watched module outputs.
  5. Open the Reclazz tool window. Call the same endpoint or method again without restarting.

For delegated Gradle or Maven runs, use the corresponding tab.

IntelliJ + SAP Commerce: keep your Ant build

  1. Install and enable Reclazz in Settings → Tools → Reclazz. Use the project’s SAP Commerce Run/Debug configuration.
  2. Start the server from IntelliJ so the plugin can inject the agent. A server started elsewhere needs the SAP Commerce setup or the documented attach route.
  3. Wait for the watcher to start. Startup attachment waits 30 seconds by default; record the current response before editing.
  4. Edit an existing Java method, then run ant build from hybris/bin/platform. Keep using the build that generates your platform classes.
  5. Check the class entry in the Reclazz tool window, then repeat the application operation in the same JVM.

Full IntelliJ and Ant workflow. AutoCompile is a separate opt-in; it is not needed for this first edit.

Gradle: Spring Boot bootRun

  1. Keep your application’s Spring Boot version. Add the Reclazz plugin using a version available in your chosen channel.
  2. Start the application with ./gradlew bootRun. The plugin attaches the agent and watches main class outputs.
  3. Wait for the Watching … directories log line, then record the current response. The watcher starts when the application reports ready, with a 30-second fallback if it receives no ready signal.
  4. Edit an existing method’s returned text. In another terminal, run ./gradlew classes.
  5. Repeat the original request without restarting. Check the response and the agent reload message.
build.gradle.kts
plugins {
    id("com.onurkat.reclazz") version "{{VERSION}}"
}
repositories { mavenCentral() }

Gradle setup and artifact availability. Plain Java application.run requires its separate opt-in.

Maven: opt-in Spring Boot profile

  1. Merge the reclazz-dev profile into your POM. Retain the application’s Boot setup and other JVM arguments.
  2. Start with mvn -Preclazz-dev reclazz:prepare-agent spring-boot:run. The profile resolves the agent separately from application dependencies.
  3. Wait for the Watching … directories log line, then record the current response. The watcher starts when the application reports ready, with a 30-second fallback if it receives no ready signal.
  4. Edit an existing method’s returned text and save. With autoCompile=true in the prepared agent argument, Reclazz compiles the edit. If prepare-agent reports “Reclazz uses Maven’s compile for this project” or you explicitly disabled automatic compilation, run mvn compile in another terminal.
  5. Repeat the original request without restarting. Check the changed response and reload message.

Saving an unfiltered resource with a supported Maven configuration updates the running application automatically. For filtered resources or other edits that need Maven processing, follow the agent’s mvn resources:resources advice.

The complete profile, artifact requirements and local build alternative stay in the Maven reference.

Plain Java: attach when the JVM starts

  1. Download the agent JAR from your chosen release, or build it from source.
  2. Add the quoted -javaagent argument at startup. Point watchDirs to the class output used by this application, not its source directory.
  3. Wait for the watcher to start. Startup attachment waits 30 seconds by default; record the current response before editing.
  4. Change an existing method’s returned text and compile into that watched output with your normal build.
  5. Call the same operation again without restarting. Check its new result and the reload message.
shell
java "-javaagent:/absolute/tools/reclazz-agent-X.Y.Z.jar=watchDirs=/absolute/app/target/classes" -cp "/absolute/app/target/classes" com.example.Main

Replace the version, paths and main class. Retain the application’s dependency classpath and other JVM options. See Windows and executable-JAR variants.
