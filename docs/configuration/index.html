Your changes and their conditions
Your changeResultBefore you try it
Edit recognized Boot properties Reloads, with a condition

Recognized Boot properties are checked for binding, conversion and validation before live mutation. Invalid or uncheckable input stays pending. Setter or recreation failure can partially apply.

Next: Fix rejected input and save again. Inspect the actual runtime values, including after a partial failure.

Edit nested YAML values or indexed lists Reloads, with a condition

Already-loaded local Boot resources with stable source/document ownership. Current native lane is Boot 2.7.18 / SnakeYAML 1.30, not all Boot versions.

Next: Edit the actual runtime file and inspect source precedence.

Delete a key or a recognized Boot file Reloads, with a condition

Removal reveals lower-priority values/defaults in the supported source path. Mutable property identities are preserved; read-only/write-only removal shapes are uncheckable.

Next: Verify resulting defaults and supported consumer rebinding.

Change active documents, imports, profiles or config locations Needs a restart

Stable source positions/document activation are prerequisites. Startup config topology is not rebuilt by a value save.

Next: Restart with the new startup configuration.

Change direct or computed @Value inputs Reloads, with a condition

Direct and supported computed values can update through their field, constructor or factory path. Each consumer has its own checks and recreation rules. Unsupported expression operations hold the candidate.

Next: Check the expression and consumer shape before retrying.

Edit a property on a loaded ordinary XML bean Reloads, with a condition

Resolved local file/context ownership plus supported value shape. Setter errors can preserve metadata but still have application side effects.

Next: Inspect the property result and independent-bean diagnostics.

Edit existing XML constructor/factory/lifecycle metadata Reloads, with a condition

Bounded ordinary singleton recreation, stable concrete type/ownership and supported direct holders. Native observer: Spring 5.3.39 / JDK 21.

Next: Check creation/destruction, repaired references and any restore failure.

Change XML scope, parent, aliases or creation policy Needs a restart

Existing metadata changes such as depends-on/primary/autowire/effective lazy flag are guarded. Supported property edits do not rebuild startup policy.

Next: Follow the bean-specific restart diagnostic.

Save unchanged unsupported XML definitions No change applied

A proven unchanged standard definition stays quiet, including known abstract/prototype shapes. Unknown/custom metadata retains conservative diagnostics.

Next: Expect no reconstruction; real unsupported edits still require restart.

Edit newly imported, remote or packaged XML Not verified yet

Captured-local discovery does not cover remote/JAR resources, pre-hook loads or a general import-topology rebuild.

Next: Edit the actually owned local resource or restart.

Edit recognized physical message bundles Reloads, with a condition

Named native Spring message-source/cache lanes; arbitrary custom basenames and automatic source-to-output copying are not established.

Next: Edit the runtime file and check a warmed formatted lookup.

Edit recognized file templates Reloads, with a condition

Named FreeMarker/Thymeleaf file-resolver lanes. Malformed saves can produce render errors; last-valid retention is not promised.

Next: Render the current output; fix malformed input and retry.

Edit resources inside packaged JAR/WAR files Not verified yet

Physical-file observers do not establish packaged-resource replacement or arbitrary view-resolver integration.

Next: Use unpacked recognized runtime resources or restart/redeploy.

Change a supported logging level/configuration Reloads, with a condition

Supported logging.level keys or logback/log4j2 config refresh. Removing a level without a fallback can still need reset/restart.

Next: Verify the target logger; keep SAP property pairs separate.

Expect arbitrary files to trigger a reload

No change applied

Reclazz recognizes specific suffixes and owned resources. It takes no reload action for an unknown kind. Your framework may independently serve that file.

Next: Check the resource classifier and your application’s resource pipeline.

Restart needed when

Changed profiles, imports and configuration locations change startup topology. Follow the config-topology row above. XML creation-policy edits have their own restart result.

Correct the input and check again

Read the pending reason before retrying. A rejected value and a partially applied framework operation are different outcomes.
