Agent options

Set common options in IntelliJ or the application JVM argument.

Choose where to set an option

Start with Settings → Tools → Reclazz in IntelliJ. For keys without a matching setting, add comma-separated key=value pairs to the application JVM’s agent argument.

Quote the complete argument when paths contain spaces. Use the installed agent version and the documented list separators.

Startup options

Common

In IntelliJ, open Settings → Tools → Reclazz for structural reload, exclusions and timing. Other keys use the startup argument below.

Application JVM argument
-javaagent:/absolute/tools/reclazz-agent-X.Y.Z.jar=startupDelaySec=30
Common options
OptionDefaultBehavior and scope
excludePatterns(none)Semicolon-separated glob patterns to exclude (e.g., *Test.class;*Mock*)
debounceMs500Milliseconds to wait before processing changes (batches rapid file writes)
startupDelaySec30Seconds to wait after agent startup before watching files
watchDirsauto-detectSemicolon-separated class output directories to watch, for a project the detection does not know
excludeClasses(none)Semicolon-separated class name patterns the transform leaves alone; the way out when instrumenting one class is the problem
structuralReloadtrueThe companion engine that adds and removes members on a stock JDK; false leaves method-body reloads only
platformautoSkip detection and name the platform (hybris, spring, generic)

SAP Commerce

In IntelliJ, open Settings → Tools → Reclazz. The SAP Commerce controls appear for a detected SAP project. Use its Install Agent action for server startup configuration.

Application JVM argument
-javaagent:/absolute/tools/reclazz-agent-X.Y.Z.jar=autoImpex=false
SAP Commerce options
OptionDefaultBehavior and scope
hybrisHomeauto-detectAbsolute path to the hybris/ directory
watchExtensionsall customSemicolon-separated extension names to watch (empty = all)
autoCompilefalseCompile .java files internally instead of watching .class files
autoImpexfalseAuto-import changed .impex files
impexAllowRemovefalseLet auto-imported ImpEx files run REMOVE lines
autoUpdateRunningSystemfalseAfter an items.xml change regenerates the models, run the schema-only Update Running System (add columns, no data, never drop) so a new attribute is live without a manual HAC click. A saved *-locales_<iso>.properties also writes the type, attribute and enumeration names it keys onto the types, as "Localize types" would for those keys only. Writes to the live database, so opt-in and dev-only
backofficeConfigResettrueAfter a module Backoffice config XML save, perform the native F4 cockpit-config reset without restarting. Resets UI-made configuration too; does not reset widgets. Set false to leave the save unapplied and use F4 manually.
autoSolrReindexfalseAfter a SAP Commerce indexing provider/resolver reload, queue a bounded native update of its existing local Solr documents. Runs normal platform listeners and bookkeeping. Development only; see targeted reindexing

Opt-in behaviour

In IntelliJ, open Settings → Tools → Reclazz for JPA refresh, static initialization and reload timing. Custom cache-owner rules use the startup argument.

Application JVM argument
-javaagent:/absolute/tools/reclazz-agent-X.Y.Z.jar=jpaRefresh=false
Opt-in behaviour options
OptionDefaultBehavior and scope
jpaRefreshfalseOpt-in mapping rebuild. Existing fields require enhanced redefinition; new entities also work on stock JDKs, including supported Hibernate validate with a prepared schema. See scope
resetStaticsfalseOpt-in reset of changed, isolated pure initializers of existing static fields; eligible static finals are made non-final at first load. Requires startup preparation; aliases keep the old object. See Changed static initializers
reloadBoundaryimmediaterequest waits for synchronous MVC dispatches and supported Spring 5 javax and Spring 6 Jakarta MVC async requests before applying a class reload batch; requires -javaagent at JVM startup. See Reload between requests
refreshOwnersOnHelper(none)Opt-in helperFqn>owner1;owner2\|helper2>owner3: after a helper class reloads, recreate the named Spring singleton cache-owner beans so a custom cache they hold is rebuilt through the fresh helper logic. Owners are recreated through the normal guarded bean-reload lifecycle; non-singletons, FactoryBeans and event-listener owners are declined. See Refreshing a custom cache after a helper reload

Diagnostics

In IntelliJ, open Settings → Tools → Reclazz for verbose logging and connection settings. Output, dump and session-log keys use the startup argument.

Application JVM argument
-javaagent:/absolute/tools/reclazz-agent-X.Y.Z.jar=verbose=true
Diagnostics options
OptionDefaultBehavior and scope
verbosefalseEnable verbose logging in the console, including each framework step's own line after a reload (the reload line carries the summary either way)
statusPort0TCP port for plugin communication (0 = auto-assign)
portFile(none)Path where agent writes its actual port after binding
wrapOutputautoWrap console lines to the terminal width: auto, true, false
transformDumpDir(none)Write every transformed class file here, for looking at what the agent emitted
verifyTransformfalseRun the bytecode verifier over every transformed class and print what it says
sessionLog(none)Append every status line to this file with an ISO timestamp and level, no colour: the session's record, to read back or attach to a report
