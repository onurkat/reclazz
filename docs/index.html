What can I change?

Start with an existing method body. For other edits, read the condition beside the result before you compile.

Six edits to start with
Your changeWhat to expectBefore you try it
Edit an existing method body ReloadsMethod-body edits reload when compiled into a watched output. Existing object fields stay in place on the JVM-only path. A separate framework refresh can recreate beans.
Add or remove a method Reloads, with a conditionAdded or removed methods work through hot-compiled callers on a stock JDK. They are not native members of the original Class. A caller using a removed method gets NoSuchMethodError, or the inherited implementation for a removed override, as after restart.
Refresh an affected singleton bean Reloads, with a conditionSupported singleton paths recreate the affected bean and repair supported references. Mutable state can reset. Arbitrary external holders are not repaired.
Add/change a controller endpoint Reloads, with a conditionSupported mapping rescans discover changed endpoints, including added methods on a stock JVM. Receiver, metadata and classloader restrictions still apply.
Edit recognized Boot properties Reloads, with a conditionRecognized Boot properties are checked for binding, conversion and validation before live mutation. Invalid or uncheckable input stays pending. Setter or recreation failure can partially apply.
Save *-items.xml / *-beans.xml Reloads, with a conditionPlatform generation and builds can reload the generated classes. Persistence, type-system updates and native reflection are separate requirements.

When a restart is needed

A superclass change needs a restart. On a stock JVM, arbitrary reflection cannot discover members added after startup.

Changing a method body preserves existing object fields. A Spring bean refresh can recreate the bean and reset its mutable state.

Understand state during a reload

How it works / Tested with

The agent watches compiled output and applies supported bytecode changes. Framework integrations then refresh supported beans, mappings and metadata.

Docs for 1.7.0. Each result has its own runtime and framework scope. Read the recorded versions and test coverage.
