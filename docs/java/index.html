Choose the edit you are making

Your changes and their conditions
Your changeResultBefore you try it
Edit an existing method body Reloads

Method-body edits reload when compiled into a watched output. Existing object fields stay in place on the JVM-only path. A separate framework refresh can recreate beans.

Next: Compile the edit, repeat the original operation and check the changed result in the same JVM.

Add or remove a method Reloads, with a condition

Added or removed methods work through hot-compiled callers on a stock JDK. They are not native members of the original Class. A caller using a removed method gets NoSuchMethodError, or the inherited implementation for a removed override, as after restart.

Next: Compile affected watched callers. Use a supported framework adapter when the operation needs reflection.

Add an instance field Reloads, with a condition

Stock mode stores added fields separately. Isolated initializers run on first read for existing objects; constructor-dependent or entangled initializers retain type defaults with a reason.

Next: Read the initializer diagnostic and verify an existing object.

Read/write an added field from another class Reloads, with a condition

Both owner and caller must be watched/reloaded in the measured direct-access shape. Field-type changes and every inherited/loader variant are not certified.

Next: Compile both sides and check the shared value on an existing object.

Add a static field with an initializer Reloads, with a condition

Compile-time constants and separable initializers, including bounded forward conditionals/switches, are supported. Other static blocks and current added-field values are preserved.

Next: Check the new value and any extraction refusal reason.

Change an already initialized static field initializer Reloads, with a condition

resetStatics=true at startup; an existing prepared physical field with a changed isolated pure initializer. Frozen first-load definalization is reflection-visible. Added fields keep execute-once behavior.

Next: Check the reset/refusal diagnostic; restart for captured aliases, constants, missing preparation or refused expressions.

Change an inlined compile-time constant Reloads, with a condition

Callers can retain their old literal until recompiled. AutoCompile can rebuild detected watched sources; unwatched consumers remain outside that repair.

Next: Recompile affected callers or use supported AutoCompile.

Append an enum constant / remove its final constant Reloads, with a condition

Documented on JDK 17–25 with ordinal-preserving edits. Existing application arrays sized from the old enum length do not grow.

Next: Check enum consumers and any fixed-size application arrays.

Insert/reorder enum values or remove a non-tail value Needs a restart

The edit renumbers ordinals; Reclazz refuses it. Restart alone does not migrate persisted ordinal data.

Next: Review persisted ordinals and restart for the type change.

Add or remove an implemented interface Reloads, with a condition

Requires a compatible enhanced-redefinition JVM such as JBR/DCEVM. Stock JVMs refuse the type change.

Next: Use a supported enhanced runtime or restart.

Change a superclass Needs a restart

The loaded superclass stays unchanged. Eligible bodies may apply; dependent methods stay pinned and unsafe signatures/constructors can refuse the whole save.

Next: Read partial/refused reporting and restart for the hierarchy.

Discover added members through arbitrary reflection Needs a restart

On stock JVMs the original Class lacks companion members. Explicit framework adapters have separate scope; arbitrary reflective consumers do not.

Next: Restart, or use a compatible enhanced JVM/explicitly supported adapter.

Assume every Java 17+ vendor/version is certified

Not verified yet

Java 17+ is the target, not certification of every runtime. The main portable records cover stock SapMachine 17/21 on macOS arm64.

Next: Validate your exact runtime and edit shape.

Restart needed when

Superclass changes, ordinal-changing enum edits and unsupported reflective access have explicit restart results above.

Terms you may see

Stock JDK
A standard JVM without enhanced class redefinition.
Companion
A hidden helper class used for added members on a stock JVM. It does not add native members to the original Class.
JetBrains Runtime (JBR)
A runtime with an enhanced redefinition path when supported and enabled. Check your runtime before using its flags.
